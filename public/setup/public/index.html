Handwritten Publish

Public hosting

You can leave the browser app public so other people can use it with their own Micro.blog tokens, while keeping your post-by-email configuration private and owner-only.

SetupPost by emailPublic hostingOpen app

What public users can do

A visitor can load images into the browser app and supply their own Micro.blog app token. The token is used only for that visitor's requests and is not persisted or logged by Handwritten Publish. Post by email remains separate and uses the deployment owner's server-side Resend and Micro.blog credentials.

What gets recorded

Handwritten Publish records only successful browser Micro.blog create or update actions and their timestamps:

[public-usage] create 2026-08-28T08:00:00.000Z
[public-usage] update 2026-08-28T08:05:00.000Z

It does not log visitor identity, Micro.blog tokens, post titles, post content, destination URLs or media URLs. Netlify still maintains its normal platform request/function logs according to your plan.

See how often it is used

Open the site's Netlify function logs and filter for public-usage. Netlify function metrics/Observability can also show invocation volume for the Micro.blog bridge functions.

Your own browser publishing appears in these counts too. Handwritten Publish deliberately does not fingerprint visitors simply to distinguish you from everyone else.

Optional email alerts

To receive one alert for every successful browser post create/update, configure all three variables:

PUBLIC_USAGE_RESEND_API_KEY
PUBLIC_USAGE_ALERT_FROM
PUBLIC_USAGE_ALERT_TO

The alert contains only the action and timestamp. It is one alert per post create/update, not per image upload. Alert delivery is best-effort and bounded; an alert problem does not turn a successful Micro.blog publish into an apparent failure.

Emergency OFF switch

To stop public browser publishing: set PUBLIC_PUBLISHING_ENABLED=false in Netlify, then trigger a fresh production deploy so the Functions receive the new environment value.

After the deploy completes, verify that a browser Micro.blog bridge request returns HTTP 503 before treating the switch as active. Local browser document editing/export still works, and the separate post-by-email endpoint is unaffected. Remove the variable or set it to true, redeploy, and verify again to enable the bridge.

Rate limits and upload cap

EndpointPer-IP limit
Micro.blog config30 requests/minute
Media uploads60 requests/minute
Draft/create/update12 requests/minute

The media bridge also caps each image at 5 MB and accepts PNG, JPEG and WebP only.

Cost backstop

Netlify's own plan-level usage/billing notifications remain the final backstop if traffic grows or the bridge is abused. If you see unusual volume, use the kill switch first and investigate the function logs afterwards.
