Handwritten Publish

Set up your own copy

Handwritten Publish is designed to work as a personal, self-hosted publishing tool. Fork or clone it, deploy your own copy, and connect it to your own Micro.blog account. The optional email workflow adds the direct reMarkable write → send → Micro.blog path.

SetupPost by emailOpen app
Quick reminder: the browser app works without any email configuration. Post by email is optional. Email posts are drafts by default; only an explicit Status: published line publishes immediately.

What you need

For the browser app: GitHub, Netlify, and a Micro.blog account if you want to publish. For post by email as well: Resend with inbound email enabled, a private incoming email address, a dedicated Micro.blog app token, and Netlify Database.

1. Fork or clone

git clone https://github.com/davidmarsden/handwritten-publish.git
cd handwritten-publish
npm install
npm test
npm run build

For local development:

npm run dev

The app is Vite/React. Production output goes to dist/; server-side bridges live in netlify/functions/.

2. Deploy to Netlify

Create a Netlify project from your GitHub fork/repository.

SettingValue
Build commandnpm run build
Publish directorydist

Netlify recognises the functions in netlify/functions/. The repository also contains a Netlify Database migration; Netlify provisions and applies it during deployment. If you only use the browser app, leave all post-by-email environment variables unset.

3. Connect Micro.blog in the browser

Paste a Micro.blog app token into the app when you want to publish. The token is kept in browser memory and passed to the Netlify bridge for the requested API calls; Handwritten Publish does not persist it in IndexedDB, .hwpublish files or Netlify configuration.

Create Micro.blog app tokens under Account → App tokens / Edit Apps. If you have several Micro.blog-hosted blogs, Handwritten Publish uses Micropub destinations to let you select one. New browser-created posts start as private drafts.

4. Optional: enable post by email

reMarkable ↓ Send by email private Resend address ↓ email.received webhook Netlify Function ↓ Micro.blog draft by default or live post when Status: published is explicit

The detailed configuration is on the Post by email page. That page includes every environment variable, the Resend webhook URL, routing examples and the handwritten title/category/status syntax.

Security summary

  • Never commit Micro.blog or Resend tokens.
  • Keep post-by-email recipient addresses private; treat them as publishing credentials.
  • Browser users supply their own Micro.blog token.
  • Post by email uses a separate dedicated server-side Micro.blog token.
  • Missing email Status: always means draft.
